# Как работать с Figma через MCP

## Начало

1. Загрузить инструменты Figma MCP одним `ToolSearch` (create_session, use_figma, get_screenshot, get_metadata, upload_assets) и прочитать скилл `figma-use` (`get_figma_skill skill://figma/figma-use/SKILL.md`), в вызовы `use_figma` передавать `skillNames: "resource:figma-use"`.
2. `create_session` с `fileKey: C7RaBUXYvu4972DadQ8qsW` и описанием задачи; полученный `sessionId` передавать во все вызовы.
3. Нужный экран найти по ID в [figma.md](figma.md). Ссылка от дизайнера вида `…?node-id=2187-27410` → узел `2187:27410`; по нему определить экран: подниматься по `parent`, пока родитель не станет `SECTION`.

## Особенности среды

- **Страница.** В начале каждого вызова `use_figma` активна первая страница. Переключаться: `await figma.setCurrentPageAsync(await figma.getNodeByIdAsync('2012:87'))`. Две смены страницы за вызов работают (служебная → рабочая), но не больше.
- **`get_metadata` по всей странице `2012:87` падает** (ответ слишком большой). Структуру получать через `use_figma` и короткие ответы (ID|имя).
- **Ответы `use_figma` > ~20 КБ** обрезаются ошибкой парсинга — возвращать компактно, кириллицу в именах можно заменять через `esc()`.
- **Шрифт Pixel Code не загружается** (`loadFontAsync` падает). Существующие тексты Pixel Code можно двигать и удалять, но не менять их содержимое и цвет. Новую надпись — собирать из контуров: `figma-scripts/px-text.js` (библиотека `L.px` со служебной страницы). Слои получаются `px·<размер>·<текст>`. Inter загружается нормально.
- **Скриншоты.** `await node.screenshot({scale})` внутри `use_figma` — удобно для проверки, но больше ~5 картинок за вызов не возвращает. `get_screenshot` даёт URL на PNG (рендер сервера). Узел внутри обрезающего контейнера (прокручиваемый поп-ап) лучше склонировать во временный фрейм вне экрана, снять и удалить.
- **GIF/видео** через MCP не работают: GIF-заливка рендерится пустой, mp4 не загружается. Анимацию дизайнер ставит вручную, файлы — `assets/city-anim/`.

## Картинки

- `upload_assets` с `nodeIds` (массив ID прямоугольников/фреймов) и `count` → получить URL, затем `curl -X POST -F "file=@путь.png;type=image/png" <submitUrl>` для каждого. Лимит 10 МБ на файл, до 60 за раз. Ответ содержит `imageHash`.
- Повторно использовать уже загруженную картинку — по хэшу: `node.fills = [{type:'IMAGE', scaleMode:'FILL', imageHash:'…'}]`. Хэши — в [illustrations.md](illustrations.md).
- Из Google Drive файлы скачиваются `download_file_content` (по 1–2 за раз, ≤ 10 МБ). Большие ответы сохраняются в `tool-results/…txt` — JSON с base64 в `content`. Но все иллюстрации уже лежат локально в `assets/illustrations/`.

## Скрипты (`figma-scripts/`)

Вставлять содержимое файла в `code` вызова `use_figma` (при необходимости поменять константы в начале).

| Файл | Что делает |
|---|---|
| `px-text.js` | Заменить надпись Pixel Code на контурную с новым текстом |
| `tabs.js` | Пересобрать все корешки поп-апов по единой форме и ширине (после смены заголовка) |
| `scrollbars.js` | Поставить/обновить/убрать скроллбары поп-апов по высоте контента |
| `glows.js` | Выровнять свечения бейджей, чипов и ползунков по киту |
| `nowrap-labels.js` | Расставить неразрывные пробелы в подписях строк показателей |
| `audit.js` | Прогнать аудит со служебной страницы по секциям |
| `proto-lib.js` | (устарело) «Динамический интерфейс»: превратить элементы экранов в интерактивные компоненты (варианты состояний по киту) |
| `proto-nav.js` | (устарело) «Динамический интерфейс»: клики, автопереходы и флоу по User Flow |
| `proto-scroll.js` | (устарело) «Динамический интерфейс»: прокрутка окон и списков, статичный фон под системными поп-апами |
| `review-screens.js` | Секции 09/10: экраны одиночной и командной игры целиком, списки развёрнуты |
| `review-popups.js` | Секция 11: все окна поп-апов в полную высоту, без прокрутки |
| `review-values.js` | Значения строк P-10 и уточнения P-11 по формулам ТЗ — в исходных окнах и копиях секции 11 (`PART`: P-11 / P-10a / P-10b) |
| `review-graphs.js` | Графики по раундам во всех P-10 (исходники и копии секции 11) по главному значению и бейджу |
| `review-p11-tabs.js` | Секция 11: все вкладки P-11 (состав по ТЗ 4.2.8.7) + первая вкладка на экранах секции 06; в конце файла — код расстановки вкладок |

## Порядок правки

1. Посмотреть узел и его окружение: структура (имена, auto-layout, размеры) + скриншот.
2. Найти образец в ките/эталоне на странице «1» и сравнить с ним (геометрия, заливки, обводки, эффекты).
3. Править сразу во всех экранах, где есть такой же элемент (искать по имени слоя через `findAll`).
4. Если менялась высота контента поп-апа — `scrollbars.js`; если заголовок окна — `tabs.js`.
5. `audit.js` + скриншоты изменённых мест. Новых замечаний аудита быть не должно.
6. Аннотацию под экраном (`annotation · <ID>`, Inter) обновить, если поменялась логика.
7. Если правка задела экраны S-08/S-07/S-09/S-10/S-11 или поп-апы — пересобрать соответствующие копии в секциях 09–11 (ниже) или поправить их тем же скриптом, что и исходники.

## Секции проверки 09–11

Копии справа от экранов (x ≥ 8880, ID в [figma.md](figma.md)). Скрипты длинные, поэтому в `use_figma` передаётся содержимое файла с параметрами в первой строке. Если вызов упал, Figma откатывает его целиком — можно просто запустить заново.

1. **09 / 10 — экраны целиком.** Удалить секцию, затем `review-screens.js` с `GROUP = 'solo', FROM = 0, TO = 3`, потом `GROUP = 'team'` частями по 8 экранов (`0–8`, `8–16`, `16–24`). Секция 10 ставится под 09.
2. **11 — поп-апы.** Удалить секцию, затем `review-popups.js` с `SRC` = ID секции-источника по порядку `2092:87`, `2096:87`, `2056:87`, `2076:88`, `2104:88`, `2110:87`, `2116:88` (повторы окон ищутся в предыдущих секциях). Перекрытие нижней панели окна — 9 px.
3. **Вкладки P-11.** `review-p11-tabs.js` с `KEY = 'P-11.01'` … `'P-11.06'` (по одному вызову; подпись вкладки может быть TEXT Pixel Code или контурной `px·`), затем код расстановки из конца файла.
4. **Значения.** `review-values.js` с `PART = 'P-11'`, `'P-10a'`, `'P-10b'` — пишет и в исходные окна, и в копии секции 11 (копии подгоняются по высоте). Потом `review-graphs.js` с `ONLY = null`.
5. `audit.js` по секциям 01–07 и скриншоты.

Числа показателей менять только вместе со связанными: список связок — в шапке `review-values.js` и в [figma.md](figma.md), раздел «Числа показателей».

## Как устроены типовые узлы

- Окно поп-апа: `modal · …` → `upper_group_close` (корешок: `pattenr_form` + текст + `Button_icon`), `pattern` (тело: вектор узора 4049×2343, `modal_container` с auto-layout и `slider`, `modal_tab_bar` снизу). Ширины окон: 560, 800, 1254 (modal_big); P-12 — 560.
- Строка показателя: `metN` / `metUp` / `metDown` — AL H, SPACE_BETWEEN, p8/24/8/24, заливка #172827, обводка #4C5152; первый TEXT — подпись, в `stat_badge_group` — значение и `Badge/secondary` (изменение).
- Карточка документооборота: `Doc_flow · Р3 · <команда>` — бейдж раунда, тег команды (`inner_wrapper` или `Badge/primary` для своей), текст.
- Нижняя панель: `control_panel` → Timer, кнопки, ` turn_panel` (имя с пробелом в начале), «приемная», «завершить ход».
