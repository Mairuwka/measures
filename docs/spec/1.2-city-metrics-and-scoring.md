Документ описывает две системы, которые не принадлежат ни одному комитету: макроэкономическую модель города (раздел 2 ТЗ Механики) и начисление баллов командам (раздел 5 ТЗ Механики). У них нет собственных инструментов: игроки только видят их и анализируют. Поэтому одна пользовательская история описывает то, что видит игрок, а правильность расчётов задают правила (Gherkin Rule) и инварианты.

## **Общие правила**

Правила R-01…R-08 едины для всех спецификаций (нумерация как в спецификации миграции). R-08 уточнено решением: пересчёт в START выполняется и в раунде 1; событий в раунде 1 нет.

|  |  |
| :-: | :-: |
| \*\*ID\*\* | \*\*Правило\*\* |
| R-01 | \*\*Какое значение читает формула.\*\* Формула берёт последнее посчитанное значение показателя на момент расчёта (внутри пересчёта – по R-GEN-02). Явная пометка «(раунд t−1)» – итог прошлого раунда, зафиксированный в END; в течение раунда не меняется. В раунде 1 значения t−1 берутся из стартового снимка S0. |
| R-02 | \*\*Когда считается ход.\*\* Расчёт хода комитета выполняется сразу после завершения его хода, затем пересчёт города (R-08). |
| R-03 | \*\*Время хода.\*\* 1,5 минуты по умолчанию, меняется ведущим на S-03. |
| R-04 | \*\*«Применить» окончательно.\*\* Деньги списываются, значение записывается, в «Документооборот» добавляется строка. Примененное решение в этом ходу нельзя уменьшить или отменить, можно докупить сверх него: ручка или кликер двигается только вверх, разница оплачивается как новая покупка. |
| R-05 | \*\*Таймер хода истёк.\*\* Непримененные изменения в открытых поп-апах сбрасываются, примененное остаётся. |
| R-06.1 | \*\*Бюджет хода общий для всех инструментов комитета.\*\* Доступный остаток = бюджет комитета на начало хода − стоимость решений, уже примененных в этом ходу − стоимость текущих значений инструментов, которые оплачиваются в конце хода и не имеют кнопки «Применить» (у туризма – SL-11). Значения, которые выбраны, но не применены, остаток не уменьшают. |
| R-06.2 | \*\*Максимум инструмента.\*\* Нельзя выбрать значение дороже, чем позволяет остаток. Если в одном окне несколько элементов, их выбранные значения считаются вместе. |
| R-06.3 | \*\*Остаток уменьшился.\*\* Если остаток уменьшился из-за действия в другом окне или из-за SL-11, максимумы во всех открытых окнах пересчитываются. Выбранное сверх максимума игра уменьшает сама: сначала значение, измененное последним, затем предыдущие. Не ниже примененного в этом ходу (R-04). Игрок видит подсказку, ошибка не показывается. |
| R-06.4 | \*\*«Недостаточно бюджета» показывается, когда:\*\* 1) игрок сам тянет инструмент дальше доступного (там, где шкала шире максимума, – SL-11, «+» кликера); 2) игрок меняет параметр, от которого зависит цена, и стоимость выбранного становится больше остатка; 3) остатка не хватает на минимальную единицу (один уровень мероприятия). |
| R-06.5 | \*\*Инструменты с оплатой по факту в конце хода.\*\* У комитета по туризму таких инструментов нет. |
| R-06.6 | \*\*Совместные инвестиции И-09 / И-14 / И-17\*\* – исключение к R-06.2–R-06.5 (спецификации бизнеса и транспорта). Предложение отправляется без проверки бюджета получателя и до принятия ничего не списывает. После принятия каждая сторона обязана оплатить свою долю полной индексированной стоимости. Доля инициатора списывается сразу при принятии, доля партнёра – в начале его ближайшего собственного хода. Списывается min(доступный остаток; непогашенная доля), остаток долга переносится на следующие раунды до погашения, бюджет не уходит в минус. Строительство создаётся один раз при принятии, объект вводится в START(t+1) независимо от долга. |
| R-07 | \*\*Слайдеры на игровом экране (SL-11, SL-12).\*\* Без «Применить», в течение хода двигаются в обе стороны, значение фиксируется, а стоимость списывается по завершении хода. Платный SL-11 уменьшает остаток своим текущим положением сразу. |
| R-08 | \*\*Пересчёт города.\*\* После хода каждого комитета – расчёт хода, затем пересчёт всех общих показателей и KPI всех комитетов. Пересчет выполняется и в START, начиная с раунда 1; события разыгрываются с раунда 2. Итоговым считается пересчёт после хода туризма; в END город заново не пересчитывается, выполняются только шаги раз в раунд. Пересчёт идемпотентен: значения t каждый раз считаются от сохраненных итогов t−1 и решений раунда, случайные значения не разыгрываются заново. Иконка изменения сравнивает с итогом прошлого раунда, точка графика UI-12 – только по итогу раунда. Исключение: KPI «Освоение миграционного потенциала» фиксируется в расчёте хода миграции по пропускной способности из пересчёта START (R-SCORE-04). |

  

### **Правила общих показателей**

|  |  |
| :-: | :-: |
| \*\*ID\*\* | \*\*Правило\*\* |
| R-GEN-01 | \*\*Только просмотр.\*\* У общих показателей нет инструментов. Они меняются только через решения комитетов, случайные события и время (инфляция, накопления). Игрок любого комитета видит их и в свой, и в чужой ход. |
| R-GEN-02 | \*\*Порядок внутри пересчёта.\*\* Пересчет идет по конвейеру (раздел «Порядок расчета»). Формула читает значение текущего пересчёта, если его шаг выше по конвейеру; иначе – итог t−1. Значение из предыдущего пересчёта того же раунда не читается никогда: так пересчёт остаётся идемпотентным и не зависит от того, сколько раз он выполнен. |
| R-GEN-03 | \*\*Шаги раз в раунд.\*\* Износ дорог (F-TRN-10), отток жителей (F-GEN-02), бросок и отъезд гениев (F-GEN-15), фиксация итогов и баллы выполняются только в END, ровно один раз. Инфляция и Коэффициент инфляции (F-GEN-12, F-GEN-13), ветшание жилья (F-URB-05), ввод объектов И-14 и сброс одно-раундовых инструментов – только в START, ровно один раз. Все эффекты события (срез стока бизнесов от итога t−1, перезапись базы E-05, множители и надбавки раунда) задаются только в START раунда события, ровно один раз. Повторный пересчёт их не повторяет. |
| R-GEN-04 | \*\*Стартовый раунд S0.\*\* В START раунда 1 считается полный пересчёт по стартовым значениям (ТЗ Механики, раздел 4) и стартовым позициям инструментов. Результат сохраняется как «раунд 0»: он показывается в BLK-01 до хода миграции, даёт точку «Старт» на графиках и служит значениями t−1 для раунда 1. Затем выполняется обычный пересчёт START. Событий в раунде 1 нет во всех режимах. |
| R-GEN-05 | \*\*Якоря.\*\* Из S0 один раз и до конца партии фиксируются: Средняя ЗП раунда 0 (база Базовой ЗП), Базовое потребление на жителя, Накопленные сбережения (раунд 0) = 0,5 × ФОТ раунда 0, Налоговые сборы (раунд 0). Решения игроков раунда 1 якоря не сдвигают. |
| R-GEN-06 | \*\*Индексация (2.1).\*\* Нормы хранятся в ценах раунда 1 и читаются только через функцию чтения нормы: Базовое значение × Коэффициент инфляции (t) × Множитель событий. Расчётные показатели (выручка, ФОТ, налоги, ВРП) и запасы (накопления, остаток бюджета) не индексируются. Единственная цепочка – Средняя ЗП. |
| R-GEN-07 | \*\*События (спецификация событий, 1.7).\*\* Потоковые показатели получают множитель и надбавку в каждом активном раунде. Все эффекты задаются в startRound сразу после розыгрыша; recalcCity события не применяет, а только читает множители раунда. Стоковые (только Общее кол-во бизнесов) – однократный срез в START раунда события от итога t−1; новые бизнесы хода бизнеса не срезаются. Перезапись базы – только у E-05 (Базовая эффективность, до конца партии). Бюджеты: множитель раунда только к доле от налоговых сборов (E-02 ×1,3, E-03 ×1,1 – по 1 раунду). Обрезка долей – последняя операция. Инерция инфляции считается от инфляции без событий. |
| R-GEN-08 | \*\*Типы и округление (2.5).\*\* Люди и штуки – целые, деньги – целые рубли, доли – дробные 0–1 (на экране 0–100%), коэффициенты могут быть больше 1, темпы роста – дробные со знаком. Промежуточные значения внутри формулы не округляются; округление (стандартное, 0,5 вверх) – при записи результата формулы. Исключение – цепочки R-BIZ-05 (открытие и закрытие фирм) и R-TUR-03 (ТТБ и отели): их промежуточные результаты хранятся дробными, округляется один раз итоговый запас.  |
| R-GEN-09 | \*\*Граничные случаи.\*\* Деление на ноль не допускается: если знаменатель темпа роста равен 0, рост = 0; если Занятые в бизнесе = 0, Целевая ЗП = Средняя ЗП (t−1) × (1 + Инфляция (t)); если Население = 0, Индекс реального спроса = 1. Отрицательные запасы не возникают: бюджет, накопления и население обрезаются снизу нулём. |
| R-GEN-10 | \*\*Отображение.\*\* Блок BLK-01 показывает последнее посчитанное значение. Иконка роста или падения и тултип UI-27 сравнивают его с итогом прошлого раунда (в раунде 1 – со снимком S0). Изменение долей показывается в п.п., остальных – абсолютной разницей и в процентах. График UI-12 содержит точку «Старт» (S0) и по одной точке на каждый завершенный раунд. |

  

# **Часть 1. Общие показатели города**

## **Место общих показателей в раунде**

Общие показатели не ходят: они пересчитываются вслед за каждым действием, которое меняет город. Поэтому команды, которые ходят позже, видят город уже с учётом решений тех, кто ходил раньше, а итог раунда фиксируется один раз в END.

|  |  |  |
| :-: | :-: | :-: |
| \*\*Фаза\*\* | \*\*Что происходит с общими показателями\*\* | \*\*Формулы\*\* |
| START (раунд 1) | Стартовый снимок S0 без событий, фиксация якорей (R-GEN-04, R-GEN-05). Событий в раунде 1 нет. Инфляция раунда 1 = 7%, Коэффициент инфляции = 1, бюджеты = 10 млрд ₽ из конфига, пересчёт города. | Все F-GEN; F-GEN-19 (раунд 1) |
| START (раунд t ≥ 2) | Событие: розыгрыш и сразу применение всех эффектов: срез стока бизнесов от итога t−1, перезапись базы E-05, множители раунда. Инфляция раунда t по итогам прошлого раунда, затем Коэффициент инфляции (t). Бюджеты комитетов по налоговым сборам t−1. Уехавшие в прошлом раунде вычитаются в формулах F-GEN-01, F-MIG-09, F-MIG-11, F-EDU-01, F-EDU-04 от снимка END (t−1). Ветшание жилья, ввод объектов И-14, сброс одно-раундовых инструментов. Пересчёт города: эффект события виден уже в ходе миграции. | F-GEN-12, F-GEN-13, F-GEN-19, F-GEN-02 (вычитание), RECALC |
| TURN-MIG | Население и Общее количество мигрантов становятся окончательными для раунда. KPI «Освоение миграционного потенциала» фиксируется. | F-GEN-01, RECALC |

## **Порядок расчёта**

Раздел описывает, какие функции расчёта вызывает игра, в какой момент партии и в каком порядке. Функции расчёта бывают двух типов: одни изменяют город, другие только считают его показатели. Все функции по очереди вызывает игровой цикл; друг друга они не вызывают, кроме startRound, который в конце вызывает recalcCity.

  

|  |  |  |  |
| :-: | :-: | :-: | :-: |
| \*\*Функция\*\* | \*\*Что делает\*\* | \*\*Когда вызывается\*\* | \*\*Сколько раз за раунд\*\* |
| \*\*Изменяют город.\*\* Каждая функция вызывается строго один раз в свой момент: повторный вызов снова прибавит мигрантов, спишет деньги или разыграет событие |  |  |  |
| \*\*startRound(t)\*\*Начало раунда | Вносит изменения, общие для всех комитетов: случайное событие, инфляция и Коэффициент инфляции, бюджеты комитетов, вычитание жителей, уехавших в прошлом раунде, ветшание жилья, ввод объектов И-14, сброс одно-раундовых инструментов. В конце вызывает recalcCity(t) | Перед ходом комитета по миграции | 1 |
| \*\*applyTurn(k)\*\*Расчёт хода комитета | Вносит изменения от решений игроков комитета k: мигранты, специалисты, новые бизнесы, площади, транспорт, отели. Формулы – в спецификации комитета | Сразу после окончания хода комитета k: игрок завершил ход или истёк таймер | 6, по одному на комитет |
| \*\*endRound(t)\*\*Конец раунда | Вносит изменения конца раунда: износ дорог, отток жителей, гении, фиксация итогов раунда, баллы и места | После пересчёта по итогам хода комитета по туризму | 1 |
| \*\*Считает показатели.\*\* Ничего не меняет в городе, только вычисляет показатели по его текущему состоянию. Повторный вызов даёт тот же результат |  |  |  |
| \*\*recalcCity(t)\*\*Пересчёт города | Пересчитывает все общие показатели и KPI всех шести комитетов по шагам из таблицы ниже | В конце startRound и после каждого applyTurn | 7: один в начале раунда и шесть после ходов |

  

Пока выполняется recalcCity, игра не обрабатывает действия игроков: функция проходит все шаги подряд, и только после этого начинается ход следующего комитета. Поэтому каждый комитет видит город с учётом всех ходов, сделанных до него в этом раунде.

Кнопка «Применить» внутри хода списывает деньги и записывает решение (R-04), но не вызывает ни applyTurn, ни recalcCity. Показатели города меняются только после окончания хода.

endRound не пересчитывает город заново. Итогом раунда считается пересчёт после хода комитета по туризму: он выполняется всегда, даже если комитет не принял решений или истёк таймер.

### **Шаги пересчёта города**

recalcCity всегда проходит шаги в этом порядке.

  

Каждый шаг читает только шаги выше или явные итоги t−1, поэтому замкнутых кругов внутри пересчёта нет. «Запасы» в таблице означают сохранённое состояние, которое пересчёт не меняет.

Почему часть значений берётся из прошлого раунда. Показатели связаны по кругу: удовлетворённость влияет на норму потребления, потребление – на инфляцию, инфляция – на удовлетворённость. Если брать всё из текущего пересчёта, результат зависел бы от того, сколько раз город пересчитали. Поэтому формула берёт значение из этого же пересчёта, только если оно посчитано на шаге выше. Иначе она берёт итог раунда t−1 (R-GEN-02). Значения из предыдущих пересчётов того же раунда не используются никогда.

Порядок шагов проверен по всем спецификациям комитетов 30.10.2026: каждый шаг читает только шаги выше или явные итоги t−1. Запасы (люди, фирмы, площади, отели, места ОТ, объекты) меняются только в startRound, applyTurn и endRound; пересчёт их не меняет.

### **Только в расчёте хода (applyTurn)**

Эти формулы меняют запасы или разыгрывают случайные значения, поэтому выполняются один раз сразу после хода комитета и в пересчёт не входят. Расчёт хода читает последние посчитанные значения (R-01), после него вызывается recalcCity.

### **Особые правила**

**KPI, которые в течение раунда не пересчитываются как обычно:**

  - «Освоение миграционного потенциала» фиксируется в расчёте хода миграции по пропускной способности из пересчёта START и до конца раунда не меняется (F-MIG-14).
  - «Качество выпуска» до хода образования показывает итог t−1 (F-EDU-08).
  - «Удовлетворение потребности бизнеса в площадях» до хода градостроя показывает итог t−1 (F-URB-12).
  - «Относительный турпоток», пока активен E-01, на экране и в баллах равен итогу до события; модель берёт фактическое значение (R-TUR-07).

**Порядок формул внутри шага 17 (транспорт).** В спецификации транспорта его нет, поэтому он записан здесь. Круга нет: доля финансирования зависит от доходов и расходов, но не от нагрузки ОТ.

1.  Транспортный спрос, плотность, нуждающиеся в ОТ (F-TRN-01).
2.  Автомобилисты = спрос × сохранённая доля автомобилистов; пассажиропоток (F-TRN-04).
3.  Распределение грузов по портам, вокзалам и грузовым дорогам, городской остаток (F-TRN-12, первая часть).
4.  Дорожный трафик (F-TRN-11).
5.  Загруженность дорожной сети и мостов, KPI «Загруженность дорог» (F-TRN-09).
6.  Проходимость и обработанный грузооборот (F-TRN-12, вторая часть); общая обеспеченность грузооборота и KPI «Покрытие нового грузооборота» (F-TRN-13, F-TRN-14).
7.  Доходы от проезда, доходы объектов, расходы на содержание (F-TRN-17…F-TRN-19).
8.  Доля финансирования содержания ОТ, сальдо (F-TRN-20).
9.  Эффективная вместимость ОТ (F-TRN-05).
10. KPI «Нагрузка на ОТ» (F-TRN-08) и «Обеспеченность ОТ» (F-TRN-07).
11. Свободная транспортная пропускная способность (F-TRN-16, она же F-GEN-25).
12. Бонус транспортной инфраструктуры (F-TRN-15).

# **Часть 2. Система баллов**

Баллы показывают, насколько хорошо команда справляется со своей зоной ответственности. Каждая команда за раунд получает от 0 до 100 баллов: по 25 за каждый из четырех KPI. Общие показатели города баллов напрямую не приносят. В разработку идут два метода – B\* (калиброванные коридоры) и D (геометрическое среднее); оба проверяются на тестах с реальными игроками, а в итоговую версию войдёт один из них (R-SCORE-07).

### **Термины**

|  |  |
| :-: | :-: |
| \*\*Термин\*\* | \*\*Что значит\*\* |
| Значение KPI | Значение основного показателя команды на момент фиксации. Хранится в долях (0,85 = 85%), Деловой климат – в баллах шкалы 20–100 |
| Красный порог / Зелёный порог | Значение, при котором и хуже которого KPI не приносит баллов / при котором и лучше которого приносит максимум |
| Коридор | KPI, у которого хорошо – попасть в зеленую зону, а отклонение и вниз, и вверх плохо. Четыре порога: нижний красный, нижний зеленый, верхний зеленый, верхний красный |
| Доля KPI | Положение Значения KPI между красным и зелёным порогом, от 0 до 1. Общая для обоих методов |
| Зона KPI | Красная – Доля = 0; зеленая – Доля = 1; желтая – между ними. Показывается игроку |
| Баллы за KPI | Сколько баллов принёс один KPI за раунд, 0–25. Хранится без округления; на экране – целым по методу наибольшего остатка (R-SCORE-06) |
| Баллы за раунд | Баллы команды за раунд, целое 0–100. Округляются один раз при фиксации |
| Итоговые баллы | Сумма Баллов за раунд по всем завершенным раундам |
| Метод | B\\\* или D. В тестовой сборке задаётся конфигом разработки, ведущий и игроки метод не выбирают. В итоговой версии остаётся один метод |

  

## **Правила системы баллов**

|  |  |
| :-: | :-: |
| \*\*ID\*\* | \*\*Правило\*\* |
| R-SCORE-01 | \*\*Когда считаются баллы.\*\* Один раз за раунд, в END, после итогового пересчёта города и фиксации итогов. Промежуточных баллов нет: в течение раунда лидерборд и «Баллы за прошлый раунд» показывают итог прошлого раунда. |

| R-SCORE-03 | \*\*Пороги\*\* – по таблице порогов (Таблица 44 ТЗ). Пороги – параметры конфига; при изменении формулы KPI их нужно откалибровать заново. |

| \*\*Формула\*\* | Баллы за раунд = округление(100 × (Π max(0,05; Доля KPI i)) ^ (1/4))Баллы за KPI i (только для экрана) = Баллы за раунд без округления × max(0,05; Доля KPI i) / Σ max(0,05; Доля KPI j) |
| \*\*Ограничения\*\* | Минимум 5 баллов за раунд. Разбивка на счёт не влияет |

  

### **F-SCORE-04. Разбивка по KPI на экране (R-SCORE-06)**

|  |  |
| :-: | :-: |
| \*\*Алгоритм\*\* | 1\\. Взять дробные Баллы за KPI.2\\. Отбросить дробные части.3\\. Недостающие до Баллов за раунд единицы отдать KPI с наибольшими дробными частями; при равенстве – KPI выше в BLK-04. |
| \*\*Ограничения\*\* | Сумма разбивки на экране = Баллы за раунд |

  

### **F-SCORE-05. Итоговые баллы (5.1.2)**

|  |  |

| \*\*Ограничения\*\* | Незавершённый раунд не оценивается (R-SCORE-08). При 10 раундах максимум 1 000 |

  

### **F-SCORE-06. Место в лидерборде (R-SCORE-09)**

|  |  |
| :-: | :-: |
| \*\*Алгоритм\*\* | 1\\. Сортировать по Итоговым баллам по убыванию.2\\. Место = 1 + число команд со строго большими Итоговыми баллами.3\\. Порядок строк внутри одного места – по Баллам за последний раунд, затем по порядку хода.4\\. Изменение места = место (t−1) − место (t): больше 0 – иконка роста, меньше 0 – падения. |
