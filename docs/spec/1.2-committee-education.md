## Общие правила

|  |  |
| :-: | :-: |
| \*\*ID\*\* | \*\*Правило\*\* |
| R-01 | \*\*Какое значение читает формула.\*\* Формула берёт последнее посчитанное значение показателя на момент расчета. Пример: комитет по образованию в свой ход видит Адаптировавшихся мигрантов без образования, уже посчитанных после хода миграции. Если в формуле явно стоит «(раунд t−1)», это итог прошлого раунда, зафиксированный в его конце; он не меняется в течение текущего раунда. В раунде 1 вместо значений t−1 используются стартовые. |
| R-02 | \*\*Когда считается ход.\*\* Расчёт хода комитета (формулы, зависящие от его решений) выполняется сразу после завершения его хода, а не в конце раунда. Сразу после расчёта хода – пересчёт города (R-08). |
| R-03 | \*\*Время хода.\*\* 1,5 минуты по умолчанию (может быть изменено на экране настройки партии у ведущего). |
| R-04 | \*\*«Применить» окончательно.\*\* После «Применить» деньги списываются, значение записывается, в «Документооборот» добавляется строка. В этом ходу примененное решение нельзя уменьшить или отменить, деньги не возвращаются. Можно применить новое решение сверх него (докупить): ручка двигается только вверх от примененного значения, разница оплачивается как новая покупка. Исключение – адаптация мигрантов (спецификация миграции). |
| R-05 | \*\*Таймер хода истёк.\*\* Изменения, выставленные в открытых поп-апах, но не примененные, сбрасываются. Примененное остаётся. |
| R-06.1 | \*\*Бюджет хода общий для всех инструментов комитета.\*\* Доступный остаток = бюджет комитета на начало хода − стоимость решений, уже примененных в этом ходу − стоимость текущих значений инструментов, которые оплачиваются в конце хода и не имеют кнопки «Применить». Значения, которые выбраны, но не применены, остаток не уменьшают. |
| R-06.2 | \*\*Максимум инструмента.\*\* Нельзя выбрать значение инструмента дороже, чем позволяет остаток. Если в одном окне несколько инструментов, их выбранные значения считаются вместе: общая стоимость не может превышать остаток. |
| R-06.3 | \*\*Остаток уменьшился.\*\* Если остаток уменьшился из-за действия в другом окне, максимумы во всех открытых окнах пересчитываются. Если выбранные значения перестали помещаться в остаток, игра сама уменьшает их до допустимых: сначала значение, измененное последним, затем предыдущие, пока общая стоимость не поместится. Значения не уменьшаются ниже уже примененных в этом ходу (R-04). Игрок видит подсказку, что выбранное значение уменьшено, ошибка не показывается. |
| R-06.4 | \*\*«Недостаточно бюджета» показывается, когда:\*\* 1) игрок сам пытается выбрать значение дороже остатка (там, где шкала шире доступного максимума); 2) игрок меняет параметр, от которого зависит цена (например, качество), и стоимость выбранного значения становится больше остатка. Выбранное значение при этом не меняется, и применить решение нельзя, пока игрок сам его не уменьшит; 3) остатка не хватает даже на минимальную единицу инструмента. |
| R-06.5 | \*\*Инструменты с оплатой по факту в конце хода.\*\* Максимум считается по текущим данным, примененное значение остаток не уменьшает, стоимость списывается по завершении хода по фактическим данным; при нехватке значение урезается пропорционально. У комитета по образованию таких инструментов нет. |
| R-07 | \*\*Слайдеры на игровом экране (SL-xx).\*\* Без кнопки «Применить», свободно двигаются в течение хода, фиксируются и оплачиваются по завершении хода. У комитета по образованию экранных слайдеров нет. |
| R-08 | \*\*Пересчёт города.\*\* После хода каждого комитета выполняется расчёт хода, а затем пересчёт города: все общие показатели и KPI всех комитетов считаются заново по текущему состоянию. Пересчет выполняется и в начале каждого раунда, после случайного события (события – с раунда 2), в том числе в раунде 1: перед ним считается стартовый снимок S0 (R-GEN-04). В конце раунда, после хода комитета по туризму, – итоговый пересчет и шаги, которые выполняются раз в раунд: отток жителей (2.3.1), бросок по гениям (2.3.20), фиксация итогов для графиков и сравнения раундов. Пересчёт можно повторять сколько угодно раз с тем же результатом: значения раунда t каждый раз считаются от сохраненных итогов t−1 и решений раунда, случайные значения не разыгрываются заново. Во время хода «Применить» показатели не меняет. Иконка роста или падения KPI сравнивает текущее значение с итогом прошлого раунда; точка на графике по раундам (UI-12) появляется только по итогу раунда. Освоение миграционного потенциала фиксируется в расчёте хода миграции по пропускной способности из пересчёта START |

  

## Место комитета в раунде

Комитет ходит вторым, сразу после миграции. На входе у него – жители без образования: остаток прошлых раундов и мигранты, которых миграция адаптировала в этом раунде (R-01). Комитет распределяет их по специальностям, строит образовательно-культурные пространства и проводит мероприятия. «Применить» только фиксирует решения и списывает деньги; специалисты, качество образования и вместимость мероприятий пересчитываются сразу после хода. Бизнес в этом же раунде видит новых специалистов, а туризм – обеспеченность досугом.

|  |  |  |
| :-: | :-: | :-: |
| \*\*Фаза\*\* | \*\*Что происходит\*\* | \*\*Формулы\*\* |
| START | Срабатывает случайное событие (с раунда 2). Считаются инфляция раунда и Коэффициент инфляции (t), а с ним цены всех инструментов. Комитет получает бюджет. Из Кол-ва человек, не получивших образование, и из Кол-ва специалистов N вычитаются уехавшие в прошлом раунде. Затем пересчёт города, в том числе в раунде 1 (после стартового снимка S0, R-GEN-04). Мероприятия раунда t еще не выбраны: до конца хода образования действуют мероприятия t−1 | F-EDU-01, F-EDU-04, F-EDU-18, бюджет (2.3.16), отток (2.3.1) |
| TURN-MIG | Миграция считает адаптировавшихся. После пересчёта растут Жители без образования, Кол-во специалистов N и меняется Качество образования по специальности (за счет адаптировавшихся с образованием) | Входы F-MIG-09, F-MIG-11; пересчёт F-EDU-01, F-EDU-04, F-EDU-06, F-EDU-07 |
| TURN-EDU | Игрок распределяет жителей по специальностям (И-05), строит здания (И-06), назначает мероприятия (И-07). «Применить» списывает деньги. Сразу после хода: Получившие образование N и их качество, бонус от мероприятий (случайные специальности разыгрываются один раз), вместимость мероприятий. Затем пересчёт города | F-EDU-02…F-EDU-17 |
| Ходы других комитетов | Бизнес получает Получивших образование N как свободных специалистов. Новые бизнесы меняют потребность в специалистах и Релевантность. Градострой передает помещения (доступны с t+1). После каждого хода – пересчёт города | Выходы F-EDU-02, F-EDU-04; пересчёт F-EDU-11, F-EDU-12, F-EDU-16, F-EDU-17 |
| END | Итоговый пересчет. Отток из групп 1–6 (Таблица 26). Бросок на появление гения по Общему качеству образования (2.3.20). Итоговые KPI попадают в график и в сравнение с прошлым раундом | F-EDU-07…F-EDU-17, 2.3.1, 2.3.20 |
| t+1 | Переданные градостроем помещения доступны для строительства. Не получившие образование снова в пуле. Мероприятия раунда t перестают действовать после хода образования в t+1 | F-EDU-01, F-EDU-13 |

## Инструменты

Каждый инструмент описан одним блоком: пользовательская история, описание инструмента, поведение в интерфейсе, что уходит в модель и сценарии проверки. Общее поведение описано в общем контракте; в блоках инструментов – только отличия.

Сценарии записаны на Gherkin: ключевые слова на английском, текст шагов на русском, числа в Examples эталонные. Теги: @turn-edu (ход образования), @round-end (конец раунда), @formula (расчет), @kpi (показатель команды), @inflation (индексация), @ui (интерфейс), @event (события), @recalc (пересчёт).

### Общий контракт инструментов

У комитета три поп-апа с кнопкой «Применить»: И-05 (P-05), И-06 (P-07), И-07 (P-05). Экранных слайдеров нет.

|  |  |  |
| :-: | :-: | :-: |
| \*\*Событие\*\* | \*\*Что происходит\*\* | \*\*Что не происходит\*\* |
| Открытие поп-апа | Ручки и кликеры стоят на значениях, уже примененных в этом ходу (в начале хода – на стартовых позициях). Максимумы считаются от остатка бюджета и от доступных людей, помещений и слотов | – |
| Движение ручки / клик | Пересчитываются предикты и итоговая стоимость по текущим положениям всех элементов поп-апа. Максимумы остальных элементов уменьшаются на выставленную сумму, выставленных людей (И-05) и занятые слоты (И-07) | Бюджет не списывается, модель города не пересчитывается |
| Стоимость больше остатка | Ручка или кликер не заходит дальше максимума. Если смена качества (И-05) до «Применить» делает стоимость больше остатка, показывается UI-32 «Недостаточно бюджета», «Применить» неактивна. То же, если остатка не хватает на одну единицу элемента | – |
| «Применить» | Бюджет проверяется заново. Значения записываются, деньги списываются, в «Документооборот» (BLK-03) добавляется строка. Поп-ап закрывается | Модель города не пересчитывается: значения прочитает расчёт хода |
| Повторное открытие в том же ходу (R-04) | Ручку и кликер можно сдвинуть только вверх от примененного значения, разница оплачивается как новая покупка.
