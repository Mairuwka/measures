## **Общие правила**

|  |  |  |
| :-: | :-: | :-: |
| \*\*ID\*\* | \*\*Правило\*\* |  |
| R-01 | \*\*Какое значение читает формула.\*\* Формула берёт последнее посчитанное значение показателя на момент расчета. Пример: комитет по градостроительству в свой ход видит Население, уже пересчитанное после хода миграции. Если в формуле явно стоит «(раунд t−1)», это итог прошлого раунда, зафиксированный в его конце; он не меняется в течение текущего раунда. В раунде 1 вместо значений t−1 используются стартовые. |  |
| R-02 | \*\*Когда считается ход.\*\* Расчёт хода комитета (формулы, зависящие от его решений) выполняется сразу после завершения его хода, а не в конце раунда. Сразу после расчёта хода – пересчёт города (R-08). |  |
| R-03 | \*\*Время хода.\*\* 1,5 минуты по умолчанию (может быть изменено на экране настройки партии у ведущего) |  |
| R-04 | \*\*«Применить» окончательно.\*\* После «Применить» деньги списываются, значение записывается, в «Документооборот» добавляется строка. В этом ходу примененное решение нельзя уменьшить или отменить, деньги не возвращаются. Можно применить новое решение сверх него (докупить): ручка двигается только вверх от примененного значения, разница оплачивается как новая покупка. Исключение – адаптация мигрантов: «Применить» фиксирует долю, а сумма списывается в расчете хода по фактическому пулу. |  |
| R-05 | \*\*Таймер хода истёк.\*\* Изменения, выставленные в открытых поп-апах, но не примененные, сбрасываются. Примененное остаётся. |  |
| R-06 | R-06.1 | \*\*Бюджет хода общий для всех инструментов комитета.\*\* Доступный остаток = бюджет комитета на начало хода − стоимость решений, уже примененных в этом ходу − стоимость текущих значений инструментов, которые оплачиваются в конце хода и не имеют кнопки «Применить». Значения, которые выбраны, но не применены, остаток не уменьшают. |
| R-06.2 | \*\*Максимум инструмента.\*\* Нельзя выбрать значение инструмента дороже, чем позволяет остаток. Если в одном окне несколько инструментов, их выбранные значения считаются вместе: общая стоимость не может превышать остаток. |  |
| R-06.3 | \*\*Остаток уменьшился.\*\* Если остаток уменьшился из-за действия в другом окне или из-за другого инструмента, максимумы бюджета, который можно выделить, во всех открытых окнах пересчитываются. Если выбранные значения перестали помещаться в остаток, игра сама уменьшает их до допустимых: сначала значение, измененное последним, затем предыдущие, пока общая стоимость не поместится. Значения не уменьшаются ниже уже примененных в этом ходу (R-04). Игрок видит подсказку, что выбранное значение уменьшено, ошибка не показывается |  |
| R-06.4 | \*\*Сообщение «Недостаточно бюджета» показывается, когда\*\*:1\.  игрок сам пытается выбрать значение дороже остатка (это возможно там, где шкала инструмента шире доступного максимума);&#10;2.  игрок меняет параметр, от которого зависит цена (например, уровень), и стоимость выбранного значения становится больше остатка. Выбранное значение при этом не меняется, и применить решение нельзя, пока игрок сам его не уменьшит;&#10;3.  остатка не хватает даже на минимальную единицу инструмента |  |
| R-06.5 | \*\*Инструменты с оплатой по факту в конце хода.\*\* Это инструменты, стоимость которых зависит от данных, известных только после хода. Их максимум считается по текущим данным так же, как в пункте R-06.2, и уменьшается по пункту R-06.3. Примененное значение остаток не уменьшает, а стоимость списывается по завершении хода по фактическим данным. Если к этому моменту денег не хватает, значение урезается пропорционально доступной сумме. |  |
| R-07 | \*\*Слайдеры на игровом экране (SL-xx).\*\* У них нет кнопки «Применить». В течение хода ручка свободно двигается в обе стороны, запрет на уменьшение (R-04) к ним не относится. Значение фиксируется, а стоимость списывается по завершении хода. Платные слайдеры уменьшают остаток бюджета своим текущим положением сразу (R-06). |  |
| R-08 | \*\*Пересчёт города.\*\* После хода каждого комитета выполняется расчёт хода, а затем пересчёт города: все общие показатели и KPI всех комитетов считаются заново по текущему состоянию. Пересчет выполняется и в начале каждого раунда, после случайного события (события – с раунда 2), в том числе в раунде 1: перед ним считается стартовый снимок S0 (R-GEN-04). В конце раунда, после хода комитета по туризму, – итоговый пересчет и шаги, которые выполняются раз в раунд: отток жителей (2.3.1), бросок по гениям (2.3.20), фиксация итогов для графиков и сравнения раундов. Население и мигранты окончательны сразу после хода миграции. Пересчёт можно повторять сколько угодно раз с тем же результатом: значения раунда t каждый раз считаются от сохраненных итогов t−1 и решений раунда, случайные значения не разыгрываются заново. Во время хода «Применить» показатели не меняет. Иконка роста или падения KPI сравнивает текущее значение с итогом прошлого раунда; точка на графике по раундам (UI-12) появляется только по итогу раунда. Освоение миграционного потенциала фиксируется в расчёте хода миграции по пропускной способности из пересчёта START |  |

## **  
****Место комитета в раунде**

Действие игрока в комитете миграции не пересчитывает город мгновенно: «Применить» только фиксирует значения инструментов. Сразу после хода выполняется расчёт хода, а затем пересчёт города: все общие показатели и KPI всех комитетов считаются заново по текущему состоянию. Пересчёт города повторяется после хода каждого комитета. Поэтому игроки видят последствия решений сразу, а комитеты, которые ходят позже, планируют с учётом новых значений (правила R-01, R-02, R-08).

|  |  |  |
| :-: | :-: | :-: |
| \*\*Фаза\*\* | \*\*Что происходит\*\* | \*\*Формулы\*\* |
| START | Срабатывает случайное событие (с раунда 2). Считаются инфляция раунда и Коэффициент инфляции (t), а с ним цены всех инструментов. Комитет получает бюджет. Вахтовики и реклама прошлого раунда обнуляются. После этого выполняется пересчёт города, в том числе в раунде 1 (после стартового снимка S0, R-GEN-04): эффекты событий видны и учитываются уже в ходе миграции. | F-MIG-16, бюджет (2.3.16), отток (2.3.1) |
| TURN-MIG | Игрок двигает ручки и видит предикты. «Применить» в поп-апе фиксирует решение и списывает деньги. Слайдеры на экране (SL-01, SL-02) фиксируются по завершении хода. Сразу после хода считаются миграционный поток и адаптация, списываются расходы на адаптацию и рекламу. Затем пересчёт города: Население и Общее количество мигрантов становятся окончательными для раунда, KPI всех комитетов обновляются. | F-MIG-01…F-MIG-12, F-MIG-16 |
| Ходы других комитетов | Образование получает адаптировавшихся без образования. Образование и бизнес получают адаптировавшихся специалистов этого раунда: миграция уже сходила (R-01). После хода каждого комитета пересчёт города: KPI миграции меняются вслед за решениями образования, бизнеса, транспорта и туризма. | Выходы F-MIG-09, F-MIG-11; пересчёт F-MIG-02, F-MIG-12, F-MIG-13, F-MIG-15 |
| END | Итоговый пересчет города после хода туризма. Раз в раунд считаются отток (2.3.1) и другие шаги конца раунда. Итоговые KPI попадают в график по раундам и в сравнение с прошлым раундом. | F-MIG-12…F-MIG-15; отток (2.3.1) |
| t+1 | Социальная напряженность и Показатель миграционной политики прошлого раунда влияют на привлекательность. Вахтовики уезжают. Неадаптированные снова входят в пул на адаптацию. | F-MIG-02, F-MIG-09 |

В таблице они обозначены «после START». Пометка «(t−1), итог END» – сохранённый итог прошлого раунда, он не меняется в течение раунда; в раунде 1 – стартовый снимок S0.

## **Инструменты**

Каждый инструмент описан одним блоком: пользовательская история, описание инструмента, поведение в интерфейсе, что уходит в модель и сценарии проверки. Поведение, общее для всех инструментов, описано один раз в общем контракте ниже; в блоках инструментов только отличия от него.

Сценарии записаны на Gherkin: ключевые слова на английском, текст шагов на русском, числа в Examples эталонные. Теги: @turn-mig (ход миграции), @round-end (конец раунда), @formula (расчёт), @kpi (показатель команды), @inflation (индексация), @ui (интерфейс), @event (события), @golden (эталонная партия).

### **Общий контракт инструментов**

Инструменты бывают двух видов: поп-апы с кнопкой «Применить» (типы P-05…P-09) и слайдеры на игровом экране без кнопки (SL-xx). Правила едины для всех шести комитетов и будут вынесены в общий документ.

### **F-MIG-16. Стоимость и списание инструментов (3.1.3, 2.1.4)**

|  |  |  |
| :-: | :-: | :-: |
| \*\*Инструмент\*\* | \*\*Норма в ценах раунда 1\*\* | \*\*Когда списывается\*\* |
| Массовая и студенческая миграция | 10 000 / 50 000 ₽ за человека (инд.) | По «Применить» |
| Отбор квалифицированных работников | 250 000 / 500 000 / 750 000 ₽ за человека (инд.) | По «Применить» |
| Вахтовая миграция | 100 000 ₽ за человека (инд.) | По «Применить» |
| Адаптация без образования / с образованием | 40 000 / 15 000 ₽ за человека (инд.) | В расчете хода по фактическому пулу |
| Миграционный контроль | Бесплатно | – |
| Реклама и PR | Процент × бюджет комитета на начало хода, не индексируется | По завершении хода |

  

Нормы читаются только через функцию чтения нормы: Базовое значение × Коэффициент инфляции (t) × Множитель событий (2.1.4). Ни одно событие нормы миграции не меняет, множитель равен 1.

Расходы на адаптацию без образования = Адаптация без образования × 40 000 (инд.) × Пул без образования. Расходы на адаптацию с образованием = Адаптация с образованием × 15 000 (инд.) × Σ Пул с образованием N. Если их сумма больше остатка бюджета, оба показателя адаптации умножаются на Остаток / Сумма расходов, после чего пересчитываются F-MIG-09 и F-MIG-10.
