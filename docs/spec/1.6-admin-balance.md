### **Обозначения**

| Обозначение | Значение |
| :---- | :---- |
| ADM-\<ГРУППА\>-xx | ID параметра в админке. Не меняется при правках ТЗ; номер раздела ТЗ указан рядом как ссылка. Группы: GAME, GEN, MIG, EDU, BIZ, URB, TRN, TOU, EVT, SCORE |
| US-ADM-01 | Пользовательская история |
| R-ADM-xx | Общее правило раздела «Баланс» в админке |
| (инд.) | Норма в ценах раунда 1, в игре умножается на Коэффициент инфляции (t). В админке вводится и хранится именно это базовое значение |
| a / b / c | Несколько значений в одной строке реестра. В админке это отдельные поля в указанном порядке |
| a–b | Диапазон или коридор: два поля – минимум и максимум |
| t / t+1 | Текущий раунд / следующий раунд |
| START, END, R-08 | Начало раунда, конец раунда и правило пересчета города – как в спецификациях комитетов |
| Раздел ТЗ | Пункт или таблица документа «ТЗ Механики WIP», где задан параметр |

## **Общие правила**

| ID | Правило |
| :---- | :---- |
| R-ADM-01 | **Что можно менять.** Только параметры из реестра ниже: стартовые значения, стоимости и пороги, в том числе пороги KPI. Также в реестре есть характеристики бизнесов, застройки, транспорта и туризма и константы случайных событий (ADM-EVT). Новый параметр сначала появляется в ТЗ, затем в реестре. |
| R-ADM-02 | **Где лежат значения.** Все параметры хранятся в конфиге баланса. Числа в коде не зашиты. Нормы с пометкой (инд.) читаются через функцию чтения нормы (2.1.4): Базовое значение × Коэффициент инфляции (t) × Множитель событий. |
| R-ADM-03 | **Когда изменение начинает действовать.** Сохранять изменения можно в любой момент, в том числе во время игры. Любое изменение конфига (стартовые значения, стоимости, пороги KPI, характеристики, параметры событий ADM-EVT) действует только в партиях, созданных после сохранения: идущая партия до конца играет на версии конфига, полученной при создании. |
| R-ADM-04 | **Ввод индексируемых норм.** Для норм (инд.) вводится значение в ценах раунда 1 |
| R-ADM-05 | **Проверка значений.** Типы и единицы – по 2.5: люди и штуки – целые не меньше 0; деньги – целые рубли не меньше 0; доли – от 0 до 1 (если единица в реестре «%», в админке вводятся проценты от 0 до 100). У диапазона минимум не больше максимума. Пороги KPI: «больше – лучше» – красный меньше зеленого, «меньше – лучше» – красный больше зеленого, коридор – нижний красный \< нижний зеленый ≤ верхний зеленый \< верхний красный. Невалидное значение не сохраняется: поле подсвечено, рядом причина. Срезы бизнесов (ADM-EVT-06, 16, 20, 22\) и перезапись базы E-05 (ADM-EVT-19) применяются один раз в START раунда события и не повторяются в следующих раундах (1.7, 1.5.4-Б и 1.5.4-Д): их длительность – не число раундов действия множителя, поле не редактируется. |
| R-ADM-06 | **Связанные параметры.** Базовые доли сезонов (ADM-TOU-01), которые в ТЗ в сумме дают 1, проверяются при сохранении. Если сумма не равна 1, показывается предупреждение, но сохранить можно: это нужно для тестов дисбаланса. Параметр, который в ТЗ стоит в нескольких формулах, – одно поле и меняется во всех формулах сразу (в реестре такие формулы перечислены в столбце «Раздел ТЗ»). |
| R-ADM-08 | **Значение по умолчанию.** У каждого параметра хранится значение из ТЗ (столбец «По умолчанию»). Поле, значение которого отличается от ТЗ, отмечено, рядом видно значение ТЗ. «Сбросить» возвращает одно поле, «Сбросить группу» – все поля раздела. |

## **Пользовательская история**

### **US-ADM-01. Настройка баланса без разработчика**

**Как геймдизайнер на тестировании, я хочу сам менять стартовые значения, стоимости и пороги в админке, чтобы лишний раз не дергать разработчика по несущественным вопросам.**

| Кто | Роль «Геймдизайнер» |
| :---- | :---- |
| Где | Админка, раздел «Баланс». Слева группы реестра (партия, общие показатели, шесть комитетов, баллы), внутри группы – три вида параметров: стартовые значения, стоимости, пороги. Поиск по ID и названию |
| Карточка поля | ID, название, значение, единица, раздел ТЗ, значение по умолчанию, подсказка  |
| Когда действует | Сохранять изменения можно в любой момент, в том числе во время игры. Любое изменение конфига (стартовые значения, стоимости, пороги KPI, характеристики, параметры событий ADM-EVT) действует только в партиях, созданных после сохранения: идущая партия до конца играет на версии конфига, полученной при создании. |
| Что не меняется | Формулы и порядок расчета; итоги и баллы уже сыгранных раундов; все параметры идущих партий (стартовые значения, стоимости, пороги, характеристики, события) |
| Правила | R-ADM-01…R-ADM-06 и R-ADM-08; функция чтения нормы (2.1.4); пересчет города (R-08) |

#### 

#### **Поведение**

| Ввод значения | Проверка по R-ADM-05 сразу при вводе. «Сохранить» активна, когда в группе есть изменения и все они валидны |
| :---- | :---- |
| Предупреждения | Сумма базовых долей сезонов не равна 1 (R-ADM-06); Сохранению не мешают |

#### 

#### **Что уходит в модель**

Сохранение создает новую версию конфига баланса. Партия при создании получает версию конфига.

### **US-ADM-02. Выбор метода начисления баллов**

**Как геймдизайнер на тестировании, я хочу в админке выбирать метод начисления баллов B\* или D для следующих партий, чтобы сравнить оба метода на живых партиях без помощи разработчика.**

| Где | Админка, раздел «Баланс», группа «Баллы» (ADM-SCORE): переключатель «Метод начисления баллов» B\* \| D. По умолчанию – B\*. Здесь же по каждой команде видны Баллы за раунд и Итоговые баллы по обоим методам |
| :---- | :---- |
| Когда действует | Сохранить новый метод можно в любой момент, в том числе во время игры. Он применяется только к партиям, созданным после сохранения: партия получает метод при создании вместе с версией конфига баланса |
| Идущая партия | Метод не меняется до конца партии. Игроки и ведущий видят баллы по методу, с которым партия создана: лидерборд, BLK-04, P-10, Итоговые баллы |
| Расчет баллов | В END всегда считаются и сохраняются баллы по обоим методам (теневой расчет, R-SCORE-07). Переключатель на расчет не влияет и ничего не пересчитывает |
| Итоговые баллы | Сумма Баллов за раунд по методу партии. В одной партии методы не смешиваются |
