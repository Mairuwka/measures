Раздел дополняет спецификацию «User Flow». Расширение города показывается сменой фона игрового экрана: на фоне играет GIF с видом города, и с ростом населения город на нем становится больше. Новых инструментов и механик модели раздел не добавляет: этап города только считывается из Населения (F-GEN-01). Порог проверяется сразу, а новый фон показывается только в начале следующего раунда.

### **Обозначения**

|  |  |
| :-: | :-: |
| \*\*Обозначение\*\* | \*\*Значение\*\* |
| Этап города | Номер фонового GIF, который сейчас показан на S-08: 0 – стартовый, 1–4 – этапы расширения |
| Достигнутый этап | Этап, до которого дорос город по Населению. Считается сервером, на экране не показывается до START следующего раунда |
| R-CITY-xx | Правило расширения города |
| US-FLOW-26 | Пользовательская история раздела. ID продолжает нумерацию User Flow |
| F-GEN-01 | Население, спецификация «Общие показатели города и система баллов» |

  

## **Общие правила**

|  |  |
| :-: | :-: |
| \*\*ID\*\* | \*\*Правило\*\* |
| R-CITY-01 | \*\*Каждый новый миллион жителей открывает следующий этап.\*\* Всего 5 фонов: стартовый (этап 0) и 4 этапа расширения. Пороги – в справочнике в конце раздела. |
| R-CITY-02 | \*\*Этап считает сервер.\*\* После каждого пересчета города (R-08) сервер сравнивает Население с порогами и записывает Достигнутый этап в состояние партии. Клиент только показывает фон по Этапу города. |
| R-CITY-03 | \*\*Этап не откатывается.\*\* Если Население упало ниже порога (например, из-за оттока жителей в START), достигнутый и показанный этапы остаются. Отток в START раунда t+1 не отменяет смену фона, заработанную в раунде t. Построенный город не исчезает. |
| R-CITY-04 | \*\*Несколько порогов сразу.\*\* Если за раунд Население перешло больше одного порога, в START следующего раунда сразу открывается самый высокий достигнутый этап. Промежуточные фоны не показываются. |
| R-CITY-05 | \*\*Город один на всех.\*\* Этап общий для комнаты: все команды и организатор в режиме наблюдения видят один и тот же фон. В одиночной игре правило то же. |
| R-CITY-06 | \*\*Только фон.\*\* Этап города не влияет на показатели, KPI, баллы и бюджеты. |
| R-CITY-07  | \*\*Новый фон – со следующего раунда.\*\* Если порог достигнут в раунде t (на практике – после хода миграции), фон до конца раунда t, на съезде и во время P-18 не меняется. В START раунда t+1, перед ходом миграции, сервер записывает Этап города = Достигнутый этап, и у всех меняется фон. |
| R-CITY-08 | \*\*Игра закончилась раньше.\*\* Если игра завершена до START следующего раунда, достигнутый, но еще не показанный этап так и не появляется на фоне. |

  

## **Место расширения в раунде**

|  |  |
| :-: | :-: |
| \*\*Фаза\*\* | \*\*Что происходит с этапом города\*\* |
| START | Население уменьшается на уехавших. Этап не снижается (R-CITY-03). Если в прошлом раунде достигнут новый этап, фон S-08 меняется перед ходом миграции (R-CITY-07). Это единственный момент, когда меняется фон |
| TURN-MIG | Население становится окончательным для раунда. Это основной момент, когда достигается новый порог: сервер записывает Достигнутый этап, фон не меняется |
| TURN-EDU … TURN-TUR | Население в раунде больше не растет, этап не меняется |
| Съезд, P-18, пауза | Пересчетов нет, этап не меняется. Фон остается прежним, даже если новый этап уже достигнут |

  

## **Пользовательские истории**

### **US-FLOW-26. Расширение города (S-08)**

**Как участник, я хочу видеть, как город растет вместе с населением, чтобы чувствовать результат решений всех комитетов не только в цифрах.**

|  |  |
| :-: | :-: |
| \*\*Экран\*\* | S-08 у всех команд и у организатора на вкладке «Наблюдение» S-07. Фон экрана – GIF текущего этапа города. Все блоки интерфейса остаются поверх фона |
| \*\*Вход\*\* | START раунда t+1, если в раунде t Достигнутый этап стал больше Этапа города (R-CITY-07) |
| \*\*Выход\*\* | Фон S-08 заменен на GIF нового этапа до начала хода миграции |
| \*\*Где не меняется\*\* | S-02…S-06, S-09, S-10, S-11 – у них свои фоны |

  

#### **Поведение**

|  |  |
| :-: | :-: |
| \*\*Смена фона\*\* | Новый GIF плавно сменяет старый за 1 секунду (исключение из R-UI-08: это фон, а не элемент интерфейса). Открытые поп-апы, таймер и ход не прерываются. В совместной игре смена происходит сразу после закрытия P-18, когда команды вернулись на S-08. В одиночной игре – после END, когда открывается S-08 комитета по миграции. Если в этом START сработало событие, P-12 открывается поверх уже нового фона |
| \*\*Достижение порога\*\* | В момент, когда Население перешло порог, на экране ничего не происходит: ни смены фона, ни уведомления. Рост населения игроки видят в BLK-01 как обычно |
| \*\*Уведомление\*\* | У всех команд в START, вместе со сменой фона, уведомление UI-40 «Город расширился: население превысило {порог}». Скрывается через 8 секунд, как информационное (ЗАМ-13) |
| \*\*Загрузка фонов\*\* | Все 5 GIF загружаются при входе в игру, до первого показа S-08, чтобы смена этапа не ждала загрузки. Пока GIF текущего этапа не загрузился, показывается его первый кадр или стартовый фон |
| \*\*Переподключение\*\* | Вернувшаяся команда сразу видит фон текущего этапа, без анимации смены и без уведомления |
| \*\*Максимальный этап\*\* | После этапа 4 фон больше не меняется, уведомлений нет |
| \*\*Одиночная игра\*\* | То же правило. Порог, достигнутый после хода миграции, меняет фон только в START следующего раунда, когда снова открывается S-08 комитета по миграции |

  

#### **Что передается серверу**

Ничего. Сервер хранит два значения: Достигнутый этап (обновляется после каждого пересчета) и Этап города (обновляется только в START). Клиентам он присылает только Этап города вместе с состоянием города. При смене Этапа города в START сервер рассылает событие «Город расширился» с номером этапа и порогом – по нему клиент запускает смену фона и уведомление.

## **Дополнительные правила**

|  |  |
| :-: | :-: |
