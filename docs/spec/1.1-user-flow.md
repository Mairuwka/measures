### **Глоссарий**

В ТЗ Дизайн и мокапах одни и те же сущности называются по-разному. В интерфейсе и коде используются названия из левой колонки.

| Термин | Синонимы в старых документах | Значение |
| :---- | :---- | :---- |
| Одиночная игра | Синглплеер | Один игрок по очереди ходит за все 6 комитетов, без таймеров и съезда |
| Совместная игра | Олимпиадный режим, соревновательный режим, мультиплеер | 6 команд, организатор, таймеры, съезд комитетов |
| Организатор | Ведущий | Создает комнату, настраивает сессию, ведет игру, единственный может завершить совместную игру |
| Участник | Игрок, команда | Команда комитета. Одна команда \= одно устройство |
| Комната | Сессия, партия | Одна совместная игра от создания на S-03 до S-11 |
| Код комнаты | – | 6 символов, по нему участник входит в комнату (P-02) |
| Сид | Seed | Число, которое задает генератор случайных чисел партии. Один сид \+ одни решения \= одна и та же партия |
| Никнейм | Username | Имя игрока в одиночной игре, под ним он попадает в лидерборд одиночной игры |
| Banword | Стоп-лист, фильтр мата | Подключаемый словарь нецензурной и оскорбительной русской лексики, по которому проверяется никнейм |

## **Общие правила**

| ID | Правило |
| :---- | :---- |
| R-FLOW-01 | **Источник правды – сервер.** Таймеры, очередь ходов, пауза, готовность команд и переходы между экранами в совместной игре определяет сервер. Клиент показывает состояние и отправляет действия. Если состояние клиента и сервера разошлось, клиент перерисовывается по серверу. |
| R-FLOW-02 | **Одна команда – одно устройство.** Комитет в комнате закреплен за одним подключением. Второе подключение на тот же комитет возможно только после отключения первого (R-FLOW-11). |
| R-FLOW-03 | **Переход закрывает поп-апы.** При смене экрана все открытые поп-апы закрываются. Непримененные изменения в поп-апах инструментов сбрасываются так же, как по таймеру (R-05). Переход S-08 → S-10 и обратно в чужой ход ничего не сбрасывает: непримененного там нет. |
| R-FLOW-04 | **Принудительные переходы.** Сервер переводит всех на S-09 в начале съезда, обратно на S-08 / S-07 после съезда и всех на S-11 по завершении игры. Переход срабатывает из любого экрана игры, включая S-10 и открытые поп-апы. |
| R-FLOW-05 | **Кнопка «Назад»** на экранах до начала игры (S-03, S-04, S-05, S-12, P-01, P-02, P-16) возвращает на предыдущий шаг. Введенные данные сохраняются до выхода в S-02. |
| R-FLOW-06 | **Возврат в игру.** Если в браузере есть активная сессия (комната в лобби или в игре), S-02 показывает кнопку «Вернуться в игру». Нажатие ведет на текущий экран сессии без повторного ввода данных. Функция обязательна. Работает по токену сессии в браузере. Если токена нет (другое устройство, очищенный браузер), команда возвращается по коду комнаты (T-08), организатор – по коду ведущего (T-23). |
| R-FLOW-07 | **Таймеры только в совместной игре.** В одиночной игре нет таймера хода, съезда, паузы и запроса паузы. Ход в одиночной игре завершается только кнопкой. |
| R-FLOW-08 | **Пауза – 5 минут, не больше.** Пауза по принятому запросу команды и пауза по кнопке организатора длятся 5 минут. Организатор может снять паузу раньше. Продлить нельзя. |
| R-FLOW-09 | **Съезд продолжается сам.** По окончании таймера съезда следующий раунд начинается без действий организатора, после минуты командного обсуждения (R-FLOW-14). |
| R-FLOW-10 | **Завершить совместную игру может только организатор** (P-14). Незавершенный раунд не оценивается (R-SCORE-08). |
| R-FLOW-11 | **Переподключение.** Если вкладка команды закрылась во время игры, команда возвращается по коду комнаты на свой комитет. Пока команды нет, ее ход идет по таймеру и завершается по R-05. Функция обязательна. Так же команда возвращается, если отключилась в лобби: комитет остаётся за ней (US-FLOW-08), вход по коду комнаты ведёт в S-06 (T-08). Организатор возвращается по коду ведущего (T-23). |
| R-FLOW-12 | **Документооборот** пополняется только строками DOC-xx. Завершение хода и начало раунда отдельной строкой не пишутся. |
| R-FLOW-13 | **Выбор комитетов – только когда собрались все.** Пока на S-04 не зашли все 6 команд, карточки комитетов заблокированы и выбрать комитет нельзя. Как только подключилась шестая команда, выбор открывается у всех одновременно и больше не закрывается. Режим переподключения (US-FLOW-21) этим правилом не ограничен. |
| R-FLOW-14 | **Минута на обсуждение после съезда.** Когда таймер съезда истек, у всех на 1 минуту открывается P-18 «Обсуждение в команде»: капитан рассказывает команде, о чем договорились на съезде. Таймеры стоят, игровые действия заблокированы. Через 1:00 начинается START следующего раунда. Сократить или продлить минуту нельзя. В одиночной игре обсуждения нет. |
| R-FLOW-15 | **Никнейм – только на русском и без мата.** Допустимы только русские буквы (включая ё), цифры, пробел и дефис. Никнейм проверяется по русскому словарю banword. Проверка на клиенте при вводе и повторно на сервере при создании партии. |

## **Место экранов в раунде совместной игры**

Раунд \= 6 ходов по 1,5 минуты (или по настройке S-03), затем съезд на 5 минут и минута обсуждения в командах. Раунды повторяются, пока организатор не завершит игру.

| Фаза | Организатор | Команда, чей ход | Остальные команды |
| :---- | :---- | :---- | :---- |
| START | S-07, P-12 при событии | S-08, P-12 при событии | S-08, P-12 при событии |
| TURN комитета N | S-07: таймер, лента | S-08 «активный ход», таймер | S-08 «ожидание», можно в S-10 |
| Конец хода N | Строки DOC-xx в ленте | Расчет хода, S-08 «ожидание» | Пересчет города; у следующей команды «активный ход» |
| END | Лидерборд обновлен | – | – |
| Съезд | S-09 \+ «Пауза», «Завершить игру» | S-09 | S-09 |
| Обсуждение в команде | P-18 поверх S-07, 1:00 | P-18 поверх S-08, 1:00 | P-18 поверх S-08, 1:00 |

## **Пользовательские истории**

Каждая история описана одним блоком: формулировка, экран и поля, поведение, что передается серверу, и сценарии проверки. Сценарии записаны на Gherkin: ключевые слова на английском, текст шагов на русском. Теги: @solo (одиночная игра), @multi (совместная игра), @host (организатор), @player (участник), @sync (действие одной роли меняет экран другой), @nav (переходы), @error (ошибки и потеря связи). На Feature не больше трех тегов.

### **US-FLOW-01. Главное меню (S-02)**

**Как игрок, я хочу сразу после открытия игры выбрать нужный режим, чтобы без муторной авторизаци начать одиночную или совместную игру.**

| Экран | S-02: логотип UI-28, кнопки «Одиночная игра», «Совместная игра», при активной сессии – «Вернуться в игру» (R-FLOW-06) |
| :---- | :---- |
| **Вход** | Открытие игры в браузере. |
| **Выход** | T-01 → S-12, T-04 → P-01, «Вернуться в игру» → текущий экран сессии |

#### **Что передается серверу**

При открытии S-02 клиент проверяет токен сессии в браузере. Сервер отвечает статусом комнаты: лобби, игра, итоги или нет. От ответа зависит кнопка «Вернуться в игру».

#### **Сценарии**

| @nav Feature: Главное меню (US-FLOW-01)   Scenario: Выбор одиночной игры     Given игрок открыл игру, активной сессии в браузере нет     When игрок нажимает «Одиночная игра»     Then открывается S-12 «Ввод никнейма»   Scenario: Выбор совместной игры     When игрок нажимает «Совместная игра»     Then поверх S-02 открывается P-01 «Выберите роль»   Scenario: Возврат в незавершенную сессию     Given команда транспорта играла в комнате с этого браузера и закрыла вкладку     And игра в этой комнате продолжается     When игрок открывает игру     Then на S-02 видна кнопка «Вернуться в игру»     When игрок нажимает «Вернуться в игру»     Then открывается S-08 комитета транспорта в текущем состоянии раунда   Scenario: Сессия завершена     Given комната из этого браузера уже на S-11 или удалена     When игрок открывает игру     Then кнопки «Вернуться в игру» на S-02 нет |
| :---- |

### **US-FLOW-02. Никнейм в одиночной игре (S-12)**

**Как игрок одиночной игры, я хочу ввести никнейм, чтобы найти себя в лидерборде одиночной игры.**

| **Строка** | Номер раунда \+ тег команды (UI-22) \+ текст из шаблона DOC-xx (справочник ниже) |
| **Что не пишется** | Завершение хода (кнопкой или по таймеру), начало раунда, движение ручек без «Применить», открытие и закрытие поп-апов (R-FLOW-12) |

#### **Поведение**

| Порядок | Новые строки сверху. Если пользователь прокрутил ленту вниз, его позиция не сдвигается |
| :---- | :---- |
| **Длина** | Строка переносится в 2–3 линии без обрезки (UI-24). Если шаблон дает больше 3 линий, то продолжение по нажатию раскрывается, а без нажатия «…» |
| **Числа** | По правилам форматирования 4.2.8.1 |
| **Теги** | Для событий без команды-автора (DOC-07) – тег «Город», для действий организатора – тег «Организатор» |

#### **Что передается серверу**

Строки формирует сервер в момент события и рассылает их клиентам, у которых открыта лента. Клиент только показывает готовый текст.

### **US-FLOW-23. Сид комнаты**

**Как организатор, я хочу задать сид комнаты, чтобы две площадки олимпиады играли с одинаковыми случайными событиями и партию можно было повторить для разбора.**

| ID | Правило |
| :---- | :---- |
| R-SEED-01 | Сид задает генератор случайных чисел партии. От него зависят все броски: событие и его выбор (Случайные события, 1.3), состав и качество массовых мигрантов (F-MIG-06), качество групп «Отбора квалифицированных работников» и вахтовиков, бросок по гениям, специальности бонуса образовательных мероприятий и прочие случайные значения спецификаций |
| R-SEED-02 | Формат: целое число от 0 до 9 999 999 999 (до 10 цифр). Ведущие нули не значимы: «0042» \= 42 |
| R-SEED-03 | Пустое поле – сервер генерирует случайный сид и сохраняет его так же, как введенный |
| R-SEED-04 | Где вводится: MULTI – поле «Сид» на S-03; SOLO – P-16 перед входом в игру |
| R-SEED-05 | Где виден: MULTI – на S-03 и на S-11 у всех; SOLO – на S-11. Во время игры участникам сид не показывается |
| R-SEED-06 | После старта игры сид не меняется |

#### **Что передается серверу**

Сид с S-03 или P-16. Хранится в состоянии партии, возвращается клиенту только для S-03 и S-11.

#### **Сценарии**

| @multi @host Feature: Сид комнаты (US-FLOW-23)   Scenario: Две площадки с одним сидом     Given организаторы двух комнат ввели сид 2026     And случайные события включены в обеих комнатах     Then в START раунда 2 в обеих комнатах одинаковый результат броска события (в раунде 1 событий нет)   Scenario: Сид на итогах     Given организатор оставил поле «Сид» пустым, сервер сгенерировал 731904     When игра завершена     Then на S-11 у всех показан сид 731904 |
| :---- |

### **US-FLOW-24. Come-back-система**

**Как участник отстающей команды, я хочу получить прибавку к бюджету, чтобы у нас оставался шанс отыграться до конца игры.**

| ID | Правило |
| :---- | :---- |
| R-CB-01 | Работает только в совместной игре и только если тумблер «Come-back-система» включен на S-03 |
| R-CB-02 | Отстающая команда \= команда с наименьшими Итоговыми баллами после END раунда t. При равенстве на последнем месте бонус получают все команды с этим результатом. Если у всех 6 команд одинаковые Итоговые баллы, бонуса нет |
| R-CB-03 | Бонус \= \+10 % к доле от налоговых сборов в бюджете комитета на раунд t+1: Временный множитель бюджета × 1,1 (F-GEN-19). Перемножается с множителями событий E-02, E-03. Остаток прошлого раунда и собственные доходы бонус не увеличивает |
| R-CB-04 | Отстающая команда определяется в END(t), бонус начисляется в START(t+1) и действует один раунд. В раунде 1 бонуса нет |

#### **Что передается серверу**

Тумблер с S-03. Отстающую команду и бонус считает сервер в END / START.

#### **Сценарии**

| @multi Feature: Come-back-система (US-FLOW-24)   Background:     Given тумблер «Come-back-система» включен     And доля от налоговых сборов без событий \= 9 750 000 000 ₽ на комитет   Scenario: Бонус последней команде     Given после END раунда 3 Итоговые баллы: миграция 230, образование 245, бизнес 210, градостроительство 260, транспорт 198, туризм 240     When начинается START раунда 4     Then доля от налоговых сборов транспорта \= 9 750 000 000 × 1,1 \= 10 725 000 000 ₽     And у остальных комитетов доля \= 9 750 000 000 ₽   Scenario: Делят последнее место     Given после END раунда 2 у бизнеса и транспорта по 150 баллов, у остальных больше     When начинается START раунда 3     Then бонус получают и бизнес, и транспорт   Scenario: Бонус вместе с событием     Given транспорт отстающий после END раунда 5     When в START раунда 6 срабатывает E-02 «Рост мировых цен на нефть»     Then доля транспорта \= 9 750 000 000 × 1,3 × 1,1 \= 13 942 500 000 ₽   Scenario: Тумблер выключен     Given тумблер «Come-back-система» выключен     When начинается START любого раунда     Then бонус не начисляется никому |
| :---- |
